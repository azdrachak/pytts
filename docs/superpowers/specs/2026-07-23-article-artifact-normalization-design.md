# Нормализация артефактов веб-статей: дизайн

## 1. Контекст

`pytts` преобразует русскоязычные статьи из Markdown и текстового PDF в MP3.
Текущий общий конвейер намеренно удаляет неподдерживаемые символы перед Silero
и сообщает о каждом удалении через warning с контекстом. Это защищает от
молчаливой потери цифр, латиницы и смысловых символов.

На двух версиях одной статьи обнаружены одинаковые потери:

- PDF из Safari: 186 блоков, 56 753 символа, 24 неподдерживаемых символа;
- исходный Markdown: 158 блоков, 56 810 символов, те же 24 символа и один
  дополнительный декоративный emoji `🎮`.

В обоих форматах некорректно читаются:

- `~28 миллиардов` как точное значение без слова «примерно»;
- `->` как оставшийся дефис после удаления `>`;
- `Petroxi`, `tax` и `Interfax` как «Петрои», «та» и «Интерфа»;
- `X5 Group` как «икс Гроуп» без числа;
- `sponsr.ru/crimsonanalytics/126423` как транслитерированный текст вместо
  удаления URL.

Видимые одинарные и двойные звёздочки на границах блоков не несут речевого
смысла. Три звёздочки в `***бать`, напротив, скрывают неизвестную часть слова:
их нельзя исправить без авторского контекста.

Проверка Markdown подтвердила, что проблема находится не в конкретном reader.
`MarkdownReader` уже снимает настоящие маркеры CommonMark и оставляет только
экранированные, намеренно видимые символы. PDF показывает те же символы
визуально. Поэтому исправление должно работать в общем конвейере после reader.

## 2. Цель

До передачи текста в Silero детерминированно нормализовать распространённые
артефакты веб-статей одинаково для PDF и Markdown, не ослабляя финальный
warn-and-strip guard.

Для контрольной статьи обе версии должны оставлять ровно три warning-записи:
по одной для каждой звёздочки в `***бать`. Все остальные обнаруженные случаи
должны либо получить корректную речевую форму, либо быть молча удалены как
декоративный контент.

## 3. Границы

### 3.1 Входит в работу

- URL без схемы, но с path, query или fragment;
- слитные uppercase буквенно-числовые коды;
- остаточный ASCII `x` после `cyrtranslit`;
- ASCII `~` и Unicode `≈` как знаки приблизительности;
- ASCII-стрелка `->` и Unicode-стрелка `→`;
- одинарные и двойные звёздочки на границах блока;
- любые Unicode emoji-последовательности;
- unit-, pipeline- и ручная реальная приёмка;
- README и runtime-зависимость для точного распознавания emoji.

### 3.2 Не входит в работу

- восстановление цензурированных слов;
- произношение emoji;
- произвольная интерпретация Markdown-подобных маркеров внутри предложения;
- неоднозначные формы десятилетий с суффиксами `-е` и `-м`, например
  `90-е/90-м` и `2020-е/2020-м`; формы `-х` уже поддерживаются;
- дроби с тремя и более десятичными знаками;
- изменение Silero, голосов, скорости, chunking или MP3-кодирования;
- reader-специфичные ветки нормализации.

Цензурированное чтение при необходимости задаётся существующим пользовательским
`transliterations`.

## 4. Выбранный подход

Исправление распределяется по существующим слоям ответственности:

1. `cleaner.py` единообразно удаляет URL со схемой, с `www` и однозначные
   URL без схемы, содержащие path, query или fragment.
2. Пользовательские `abbreviations` и `transliterations` сохраняют текущий
   приоритет.
3. `numeric_normalizer.py` раскрывает слитные uppercase-коды с цифрами.
4. `pronunciation.py` нормализует речевые символы, граничные звёздочки и emoji.
5. `latin.py` исправляет остаточный `x` после общей транслитерации.
6. `_strip_unspeakable` остаётся последней защитой и формирует warning только
   для действительно неизвестного остатка.

PDFReader и MarkdownReader не меняются. Новый общий слой или новая абстракция
не вводятся: существующие файлы остаются небольшими и уже соответствуют этим
обязанностям.

## 5. Поток данных

Порядок конвейера остаётся:

```text
InputReader
  -> PDFReader | MarkdownReader
  -> clean_article
  -> AbbreviationExpander
  -> TransliterationOverrides
  -> NumericNormalizer
  -> symbol and emoji normalization
  -> normalize_latin
  -> warn-and-strip guard
  -> chunk_article
  -> Silero
```

Важные следствия порядка:

- однозначный bare URL удаляется до пользовательских замен и транслитерации;
- `X5` раскрывается до общей латинской транслитерации и финального guard;
- пользовательская замена может перехватить цензурированную или нестандартную
  запись до встроенных правил;
- знак приблизительности обрабатывается после чисел, поэтому `~28` становится
  «примерно двадцать восемь»;
- неизвестный остаток по-прежнему виден пользователю в warning.

Внутри `NumericNormalizer.normalize` новое правило слитного кода использует
границы `(?<!\w)` и `(?!\w)` и обязательно выполняется до
`_REMAINING_INTEGER`. Иначе цифра в `X5` останется внутри буквенного токена и
не будет раскрыта.

Внутри `PronunciationNormalizer` correctness-critical порядок после
пользовательских замен и числовой нормализации фиксируется так:

1. удалить оставшиеся emoji-последовательности целиком;
2. снять одинарные и двойные звёздочки на границах блока;
3. заменить `->` и `→` двоеточием;
4. заменить одиночную `~` и `≈` словом «примерно»;
5. применить существующую таблицу речевых символов;
6. нормализовать пробелы;
7. транслитерировать оставшуюся латиницу и исправить остаточный `x`;
8. передать остаток финальному warn-and-strip guard.

Emoji удаляются до граничных звёздочек, поэтому keycap-композиция `*️⃣`
исчезает целиком и не превращается в ложный Markdown-маркер или warning о `*`.

## 6. Правила

### 6.1 URL без схемы

Cleaner распознаёт:

- `https://example.com/path`;
- `http://example.com/path`;
- `www.example.com/path`;
- `sponsr.ru/crimsonanalytics/126423`;
- `example.com?q=1`;
- `example.com#section`.

Все три ветки — scheme, `www` и bare — используют одну реализацию границ и
одинаково сохраняют завершающую пунктуацию.

Однозначный bare URL:

- использует ASCII hostname;
- содержит хотя бы одну точку;
- имеет буквенную зону длиной не менее двух символов;
- обязательно имеет path, query или fragment;
- не начинается внутри слова или email;
- не поглощает завершающие `.`, `,`, `;`, `:`, `!`, `?`, `…`, `)`, `]`, `}`
  и кавычки.

Host-only токен без scheme и `www` считается неоднозначным и сохраняется. Это
fail-open решение защищает имена файлов и смысловой текст:

- `main.py`, `README.md`, `config.yaml`, `index.html` сохраняются;
- `example.com` без path, query и fragment также сохраняется;
- `sponsr.ru/crimsonanalytics/126423` удаляется.

Компромисс принят явно: отдельный голый домен может попасть в озвучку, но
неоднозначный токен не удаляется молча. Видимый текст Markdown-ссылки
сохраняется, если он не соответствует однозначному URL-правилу. Если label сам
является path-bearing URL, он удаляется тем же правилом.

### 6.2 Слитные коды

Отдельный токен, соответствующий `[A-Z]{1,5}\d+`, читается как английские
названия букв и русское количественное числительное:

- `X5` -> «икс пять»;
- `FPV5` -> «эф пи ви пять».

Строчные слова с цифрами, части более длинных идентификаторов и существующие
коды с дефисом не затрагиваются. `F-16` продолжает читаться текущим правилом.

### 6.3 Остаточный `x`

`cyrtranslit` оставляет ASCII `x` в ряде обычных слов. После успешной
транслитерации обычного латинского слова остаточные:

- `x` заменяются на `кс`;
- `X` заменяются на `Кс`.

Примеры:

- `Petroxi` -> «Петрокси»;
- `tax` -> «такс»;
- `Interfax` -> «Интерфакс».

Одиночная uppercase `X` и группы uppercase-букв сначала проходят существующее
чтение по названиям букв и не попадают под это правило.

Правило механическое и не пытается определять английскую фонетику по контексту.
Mixed-case слова вроде `Xi` могут получить приблизительное чтение «Кси»;
точные имена и исключения по-прежнему задаются через `transliterations`.

### 6.4 Знак приблизительности

Одиночная тильда, не соседствующая с другой тильдой, и Unicode-знак `≈`
заменяются словом «примерно»:

- `~28 миллиардов` -> «примерно двадцать восемь миллиардов»;
- `~7%` -> «примерно семь процентов».
- `≈ 25%` -> «примерно двадцать пять процентов».

`~~текст~~` не трактуется как приблизительное значение и остаётся финальному
guard.

### 6.5 Стрелка

ASCII-последовательность `->` и Unicode-стрелка `→` заменяются двоеточием.
Пробелы вокруг результата проходят существующую нормализацию:

```text
рекомендую к прочтению -> название
рекомендую к прочтению: название
```

### 6.6 Граничные звёздочки

На начале и конце каждого `TextBlock`, после учёта окружающих пробелов,
удаляется последовательность ровно из одной или двух звёздочек:

- `**это не рекомендация**` -> `это не рекомендация`;
- `** Данная информация` -> `Данная информация`;
- `решения **` -> `решения`;
- `*Данный документ*` -> `Данный документ`.

Последовательность длиной три и более не меняется. Звёздочка внутри блока также
не считается оформлением:

- `***бать` остаётся для warning;
- `2 * 3` остаётся для warning.

Это намеренно узкое правило закрывает наблюдаемые артефакты и не пытается
повторно реализовать Markdown parser.

### 6.7 Emoji

Все Unicode emoji-последовательности, оставшиеся после пользовательских
`transliterations`, удаляются молча до финального guard:

- одиночные emoji;
- variation selectors;
- модификаторы тона кожи;
- флаги;
- ZWJ-композиции.

Для полного Unicode-покрытия добавляется runtime-зависимость `emoji>=2,<3`;
самодельный список диапазонов не используется. После обычного `uv sync` пакет
использует локальную таблицу emoji и не выполняет сетевых запросов во время
нормализации или синтеза; офлайн runtime-контракт `pytts` сохраняется.

Если после удаления emoji блок пуст, блок отбрасывается. Если после всей
нормализации статья не содержит речевых блоков, сохраняется существующий
`InputError`.

## 7. Ошибки и предупреждения

Новые exit-коды и классы ошибок не добавляются.

Финальный guard продолжает:

- молча пропускать поддерживаемый текст;
- удалять неизвестные неподдерживаемые символы;
- сообщать количество, символ и окружающий контекст;
- выбрасывать `InputError`, если речевого текста не осталось.

URL и граничные звёздочки молча удаляются только при совпадении с узкими
структурными правилами раздела 6. Среди произвольных Unicode-классов только
emoji получают новое правило молчаливого удаления независимо от позиции в
тексте; это происходит до финального guard. Сам guard не получает новых
молчаливых исключений. Цензурированные звёздочки и математическая `*`
продолжают формировать warning.

## 8. Тестирование

### 8.1 Unit-тесты

`tests/text/test_cleaner.py`:

- URL со схемой, `www` и однозначный path-bearing bare URL;
- путь, query и fragment;
- одинаковое сохранение завершающей пунктуации для всех URL-веток;
- `main.py`, `README.md`, `config.yaml`, `index.html` и host-only
  `example.com` сохраняются;
- email, десятичная точка и обычное предложение не дают ложного совпадения.

`tests/text/test_numeric_normalizer.py`:

- `X5` и `FPV5`;
- границы `(?<!\w)` и `(?!\w)`;
- выполнение до `_REMAINING_INTEGER`;
- отсутствие регрессии для `F-16`, диапазонов и обычных чисел;
- идемпотентность.

`tests/text/test_latin.py`:

- `Petroxi`, `tax`, `Interfax`;
- отдельная `X`, uppercase-коды, mixed-case `Xi` и обычные слова;
- идемпотентность.

`tests/text/test_pronunciation.py`:

- одиночная `~`, `≈` и `~~`;
- `->` и `→`;
- одинарные и двойные звёздочки на обеих границах блока;
- `***` и математическая `*`;
- одиночные и составные emoji, включая keycap `*️⃣`;
- emoji удаляется до граничных звёздочек;
- блок, состоящий только из emoji;
- предупреждение для неизвестного остатка.

`tests/test_pipeline.py`:

- пользовательские `transliterations` применяются раньше встроенных правил;
- warning события содержат только оставшийся неподдерживаемый текст.

### 8.2 Интеграционная фикстура

Добавляется короткая Markdown-фикстура, воспроизводящая все классы артефактов
контрольной статьи без копирования полного стороннего текста. Она содержит:

- граничные `*` и `**`;
- `***бать`;
- `~28`, `≈25`, `->`, `→`, `Petroxi`, `windfall tax`, `X5 Group`, `Interfax`;
- path-bearing bare URL и сохраняемые `main.py`/`config.yaml`;
- простой emoji, keycap и ZWJ-композицию.

Ожидаемый warning содержит только три записи `*` из `***бать`. Это контракт
данной фикстуры, а не общий инвариант нормализатора.

### 8.3 Реальная приёмка

Предоставленные пользователем файлы не коммитятся:

- `/Users/azdrachek/Downloads/Новостной деск.pdf`;
- `/Users/azdrachek/Downloads/Новостной деск Апдейты по акциям Русского списка.md`.

Для каждого файла выполняется текстовый прогон без синтеза. Следующие ожидания
относятся только к этим двум зафиксированным версиям контрольной статьи:

- warning содержит ровно три звёздочки из `***бать`;
- «Петрокси Традинг»;
- «виндфалл такс»;
- «икс пять Гроуп»;
- «Интерфакс»;
- «примерно двадцать восемь миллиардов»;
- целевой path-bearing bare URL отсутствует;
- `🎮` отсутствует без warning.

После этого короткий контрольный текст синтезируется реальной кэшированной
Silero-моделью при отключённой сети. MP3 должен быть валидным, mono, 48 kHz и
96 kbit/s.

Финальный gate:

```bash
uv run pytest -m "not silero"
PYTTS_RUN_SILERO=1 uv run pytest -m silero
uv run ruff check .
uv lock --check
git diff --check
```

## 9. Документация

README получает точные правила:

- URL со scheme/`www` и path-bearing bare URL удаляются, неоднозначные host-only
  токены сохраняются;
- одиночная тильда и `≈` читаются как «примерно»;
- `->` и `→` превращаются в речевую паузу через двоеточие;
- слитные uppercase-коды поддерживаются;
- остаточный `x` после транслитерации читается как `кс`;
- любые emoji, оставшиеся после `transliterations`, удаляются молча;
- одинарные и двойные граничные звёздочки удаляются;
- цензурированный или неизвестный остаток продолжает появляться в warning;
- точное произношение задаётся через `transliterations`.

Существующий пункт README «Greek and other non-Cyrillic letters, emoji, and
unknown semantic symbols are dropped with a warning» изменяется явно: Greek и
неизвестные смысловые символы по-прежнему дают warning, а оставшиеся после
пользовательских замен emoji удаляются молча.

`pyproject.toml` получает `emoji>=2,<3`, `uv.lock` обновляется.

## 10. Критерии готовности

Работа готова, когда:

1. Все правила из раздела 6 имеют RED/GREEN unit-тест.
2. Минимальная интеграционная фикстура оставляет только три warning-записи.
3. Обе реальные версии статьи проходят критерии раздела 8.3.
4. Реальный Silero создаёт валидный контрольный MP3 без сети.
5. Полный тестовый и статический gate проходит.
6. README и lock-файл соответствуют реализованному поведению.
7. Финальный code review не содержит Critical или Important замечаний.
